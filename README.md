# ระบบจัดเก็บคำสั่งและประกาศศาล (GDMS - Official Order Numbering System)

เอกสารสรุปรายละเอียดคุณลักษณะ โครงสร้างระบบ และคู่มือการใช้งานเบื้องต้น สำหรับ **ระบบออกเลขและจัดเก็บคำสั่ง/ประกาศศาล** ที่พัฒนาด้วยภาษา Python เพื่อใช้งานภายในเครือข่ายอินทราเน็ต (LAN) ของหน่วยงาน

---

## 1. ภาพรวมของระบบ (System Overview)

ระบบนี้ออกแบบมาเพื่อทดแทนหรือยกระดับระบบสารบรรณอิเล็กทรอนิกส์ (GDMS) ในส่วนของ **การจัดเก็บและออกเลขคำสั่ง/ประกาศ** โดยเน้นความสะดวกในการใช้งาน ความถูกต้องของลำดับเลขรันอัตโนมัติ และการจัดเก็บไฟล์เอกสารสแกนอย่างเป็นระบบ

### ประเภทเอกสารที่รองรับ (4 ประเภท)
1. **คำสั่งศาล**
2. **คำสั่งสำนักงาน**
3. **ประกาศศาล**
4. **ประกาศสำนักงาน**

---

## 2. คุณสมบัติหลัก (Key Features)

### 2.1 ระบบรันเลขคำสั่ง/ประกาศอัตโนมัติ
- **แยกตามประเภทเอกสาร:** เอกสารทั้ง 4 ประเภทจะรันเลขแยกอิสระต่อกัน (เช่น `คำสั่งศาล ที่ 1/2569`, `คำสั่งสำนักงาน ที่ 1/2569`)
- **รีเซ็ตตามปี พ.ศ. อัตโนมัติ:** ระบบอ้างอิงปี พ.ศ. จาก **"ลงวันที่"** ของเอกสาร เมื่อขึ้นปี พ.ศ. ใหม่ (ตั้งแต่วันที่ 1 มกราคม) ระบบจะเริ่มนับเลข `1` ใหม่โดยอัตโนมัติ
- **แสดงเลขถัดไปแบบ Real-time:** ในหน้าออกเลข เมื่อเลือกประเภทเอกสารหรือเปลี่ยนวันที่ ระบบจะแสดงพรีวิวเลขที่จะได้รับทันทีก่อนกดบันทึก
- **ตั้งค่าเลขเริ่มต้นได้ (สำหรับย้ายระบบกลางปี):** ผู้ดูแลระบบสามารถกำหนดเลขเริ่มต้นของแต่ละประเภทในแต่ละปี พ.ศ. ได้ (เช่น ตั้งค่าเลขเริ่มต้นของคำสั่งศาลเป็น `119` เพื่อให้ระบบรันเลขต่อจากสมุดคุมเดิมได้ทันที)
- **ป้องกันเลขชนกัน (Concurrency Safe):** ใช้ Transaction (`BEGIN IMMEDIATE`) ของ SQLite และ Unique Constraint `(doc_type, doc_year, doc_number)` ป้องกันปัญหาการกดขอเลขพร้อมกันหลายเครื่องในวง LAN

### 2.2 การจองเลข และการแนบ/แก้ไขไฟล์เอกสารสแกน
- **สถานะ "จอง" (สีส้ม):** หากผู้ใช้งานบันทึกออกเลขโดยยังไม่ได้แนบไฟล์ ระบบจะกำหนดสถานะเป็น **"จอง"** เพื่อล็อกเลขที่คำสั่งไว้ก่อน
- **สถานะ "จัดเก็บ" (สีเขียว):** เมื่อมีการแนบไฟล์เอกสารที่ได้จากการสแกน (`.pdf`, `.jpg`, `.jpeg`, `.png`) ระบบจะเปลี่ยนสถานะเป็น **"จัดเก็บ"** โดยอัตโนมัติ
- **การแก้ไขและแนบไฟล์ตามหลัง:** สามารถกลับมาแก้ไขรายละเอียดเรื่อง วันที่ หมายเหตุ รวมถึงอัปโหลดไฟล์แนบตามหลัง เปลี่ยนไฟล์ใหม่ทับไฟล์เดิม หรือลบไฟล์แนบเพื่อเปลี่ยนสถานะกลับเป็น "จอง" ได้ตลอดเวลา
- **เปิดดูเอกสาร (Preview) ในเว็บทันที:** คลิกที่เลขคำสั่งหรือปุ่มไอคอนคลิปหนีบกระดาษสีเขียว เพื่อเปิดหน้าต่างพรีวิวไฟล์ PDF และรูปภาพบนหน้าเว็บได้ทันทีโดยไม่ต้องดาวน์โหลดลงเครื่องก่อน

### 2.3 ระบบแฟ้มเก็บและการค้นหาข้อมูล
- **ตัวกรองแบบละเอียดเหมือนระบบ GDMS เดิม:** รองรับทั้งการค้นหารวมทุกคอลัมน์ (Global Search) และช่องค้นหาแยกตามคอลัมน์ (`#`, `คำสั่ง/ลำดับ`, `สถานะ`, `ประเภท`, `เรื่อง`, `ลงวันที่`, `ผู้บันทึก`)
- **การ์ดสรุปข้อมูลประจำปี:** แสดงยอดรวมเอกสาร ยอดจัดเก็บแล้ว ยอดจองเลข และเลขถัดไปของทั้ง 4 ประเภทที่ด้านบนของหน้าแฟ้มเก็บ

### 2.4 ระบบรายงาน สมุดคุม และการส่งออกข้อมูล
- **แดชบอร์ดสรุปผล (Dashboard):** สรุปจำนวนเอกสารแยกตามประเภทและสัดส่วนสถานะ (จัดเก็บแล้ว / จองเลข)
- **ส่งออกไฟล์ Excel (`.xlsx`):** ส่งออกรายการตามเงื่อนไขที่กรอง (ปี พ.ศ., ประเภท, สถานะ, ช่วงวันที่) พร้อมจัดรูปแบบตารางและฟอนต์ราชการ (`TH SarabunPSK`)
- **พิมพ์สมุดคุมทะเบียนคำสั่ง/ประกาศ:** หน้าสำหรับสั่งพิมพ์ (Print) ลงกระดาษ A4 หรือบันทึกเป็นไฟล์ PDF เพื่อใช้เป็นสมุดคุมทะเบียนเอกสารราชการ

### 2.5 ระบบผู้ใช้งานและสิทธิ์การเข้าถึง (Role & Permission)
แบ่งระดับผู้ใช้งานเป็น 2 ระดับ:
1. **ผู้ใช้งานทั่วไป (`user`):**
   - ออกเลขคำสั่ง/ประกาศได้ทุกประเภท
   - เปิดดูพรีวิวไฟล์ ดาวน์โหลดไฟล์ และดูรายงาน/ส่งออก Excel ได้ทั้งหมด
   - แก้ไขข้อมูลและแนบ/เปลี่ยนไฟล์ได้ **เฉพาะรายการที่ตนเองเป็นผู้บันทึก**
2. **ผู้ดูแลระบบ (`admin`):**
   - มีสิทธิ์เหมือนผู้ใช้งานทั่วไปทั้งหมด
   - สามารถแก้ไขหรือลบเอกสารได้ **ทุกรายการ** ของทุกคน
   - ตั้งค่าเลขเริ่มต้นประจำปี พ.ศ. และเปลี่ยนชื่อหน่วยงานได้
   - เพิ่ม/แก้ไข/ระงับบัญชีผู้ใช้งาน และรีเซ็ตรหัสผ่านให้เจ้าหน้าที่ได้

## 3. สถาปัตยกรรมและเทคโนโลยีที่ใช้ (Tech Stack)

| ส่วนประกอบ | เทคโนโลยี / ไลบรารี | รายละเอียด |
| :--- | :--- | :--- |
| **Backend Framework** | Python 3 + **Flask** | จัดการ Routing, Authentication, File Upload และ API |
| **WSGI Production Server** | **Waitress** | เซิร์ฟเวอร์แบบ Multi-threaded สำหรับรองรับการใช้งานพร้อมกันในวง LAN |
| **Database** | **SQLite 3** (WAL Mode) | เก็บข้อมูลในไฟล์ `data/gdms.db` ไม่ต้องติดตั้ง Database Server แยก |
| **Excel Generator** | **OpenPyXL** | สร้างไฟล์สมุดคุม `.xlsx` พร้อมจัดรูปแบบตาราง |
| **Frontend UI** | **Bootstrap 5.3** + **Bootstrap Icons** | ดีไซน์ทันสมัย รองรับหน้าจอทุกขนาด ใช้ฟอนต์ **Sarabun** |

## 5. โครงสร้างตารางฐานข้อมูล (Database Schema)

1. **`users`** — เก็บข้อมูลบัญชีผู้ใช้งาน
   - `id`, `username`, `password_hash`, `full_name`, `position`, `role` (`admin`/`user`), `is_active`, `created_at`
2. **`documents`** — เก็บข้อมูลคำสั่งและประกาศ
   - `id`, `doc_type`, `doc_number`, `doc_year`, `title`, `doc_date`, `status` (`reserved`/`stored`), `file_path`, `original_filename`, `file_type`, `file_size`, `note`, `created_by`, `updated_by`, `created_at`, `updated_at`
3. **`number_configs`** — เก็บค่าเลขเริ่มต้นของแต่ละประเภทในแต่ละปี พ.ศ.
   - `id`, `doc_type`, `doc_year`, `start_number`, `updated_at`
4. **`system_settings`** — เก็บค่าตั้งค่าระบบ เช่น ชื่อหน่วยงาน (`org_name`) และชื่อระบบ (`system_title`)

## 6. การติดตั้งและเปิดใช้งานระบบผ่าน LAN

### 6.1 การเปิดใช้งานปกติ (ผ่านไฟล์ Batch)
1. ดับเบิลคลิกที่ไฟล์ **`start_lan_server.bat`**
2. หน้าต่างโปรแกรมจะแสดง IP Address ของเครื่องเซิร์ฟเวอร์ เช่น:
   - เข้าใช้งานจากเครื่องเซิร์ฟเวอร์: `http://localhost:5000`
   - เข้าใช้งานจากเครื่องอื่นในวง LAN: `http://192.168.x.x:5000`
3. เครื่องคอมพิวเตอร์อื่นในสำนักงานที่อยู่ในวง LAN เดียวกัน สามารถเปิดเว็บเบราว์เซอร์ (Chrome, Edge) แล้วพิมพ์ URL ดังกล่าวเพื่อเข้าใช้งานได้ทันที

> **ข้อแนะนำสำหรับ Windows Firewall:** หากเครื่องอื่นในวง LAN เข้าไม่ได้ในครั้งแรก ให้กด **Allow access (อนุญาตการเข้าถึง)** เมื่อ Windows Firewall แจ้งเตือน หรือเปิดพอร์ต TCP `5000` ใน Windows Defender Firewall

## 7. การสำรองข้อมูล (Backup & Restore)

ข้อมูลทั้งหมดของระบบถูกจัดเก็บไว้ใน 2 โฟลเดอร์หลักภายในโปรเจกต์:
1. โฟลเดอร์ **`data/`** (เก็บไฟล์ฐานข้อมูล `gdms.db`)
2. โฟลเดอร์ **`uploads/`** (เก็บไฟล์สแกน PDF และรูปภาพทั้งหมดแยกตามปี พ.ศ.)

**วิธีสำรองข้อมูล:** เพียงคัดลอก (Copy) ทั้ง 2 โฟลเดอร์นี้เก็บไว้ในไดรฟ์สำรอง หรือ External Drive ตามรอบระยะเวลาที่ต้องการ
